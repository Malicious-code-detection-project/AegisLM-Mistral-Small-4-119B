# B200 Source Sync Report — 2026-08-25

## 결론

B200 standalone Mistral project에는 Git metadata가 있었지만 유효한 commit과 remote가
없었다. 기본 branch 이름은 `master`였으며 code, config와 lockfile을 포함한 모든 작업
파일이 untracked였다. 로컬에는 해당 standalone source 저장본이 없고 wiki 문서만
존재했다.

따라서 B200를 source of truth로 삼아 GitHub 보존용 local snapshot을 새로 만들었다.

## 로컬에서 의도적으로 변경한 파일

GitHub 저장 전에 다음 portable·privacy·format 변경만 적용했다.

1. `.gitignore`: artifact, tool, test/lint cache와 serving compilation cache 경계를 추가했다.
2. `README.md`: 비어 있던 파일에 목적, 환경 분리, 상태와 저장 경계를 작성했다.
3. `scripts/check_serving.sh`: 사용자 홈 절대경로를 repository-relative/environment 변수로
   교체하고, B200에서 검증된 executable compilation cache, 짧은 IPC temp와
   `enable_cutedsl_warmup: false` text-only workaround를 반영했다.
4. `.gitattributes`: Windows checkout에서도 Python·shell·YAML·TOML·lockfile을 LF로
   유지하도록 추가했다.
5. `configs/g1-qlora-ddp-1step.yaml`, `scripts/checkpoint_idx.py`,
   `scripts/g3_artifact.sh`: trailing whitespace와 EOF blank line만 정리했다.

위에서 명시한 6개 원본 파일을 제외한 34개 source snapshot은 B200와 동일하다.
`.gitattributes`와 두 sync 문서는 local에서 새로 추가했다. 로컬 변경을 B200에
역동기화한 것은 아니며, server-side project는 이번 작업에서 수정하지 않았다.

## 남은 차이

- B200에는 학습·평가·서빙 artifact와 cache가 있지만 local/GitHub에는 없다.
- B200 repository에는 commit·remote가 없고 local snapshot이 최초 version-control
  baseline이 된다.
- vLLM base-only Chat Completions는 PASS했지만 G3 LoRA attach는 별도 compatibility
  gate다.

## 보존 원칙

GitHub repository는 private으로 생성한다. model, dataset, adapter와 secret은 Git LFS로도
올리지 않으며, 필요한 경우 hash와 persistent storage 위치 계약만 문서화한다.
